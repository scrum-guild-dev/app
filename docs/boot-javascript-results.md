# 初回表示の JavaScript（#1071）

## 採用した方法

SvelteKit の画面ごとの分割は残し、client 環境だけで Svelte の実行コード、初回にも使う操作の定義、基本部品をまとめる。全 `node_modules` や全画面を1つにはしない。操作の定義も Wiki・接続・スプリントなどを一律に含めず、今日と組織の枠で使う領域を指定する。

`AppShell` の起票シートは、最初に起票ボタンを押したときに読む。本文編集のコードもこの時点まで読まない。連打はまとめ、画面を移った後や部品が外れた後に古いシートを開かない。読み込み中は `aria-busy` で知らせ、300msを超えたら既存のトースト領域で「読み込んでいます」を表示・読み上げする。失敗は既存の失敗トーストで知らせ、「画面を読み直す」からページを再読み込みできる。作成・破棄確認・フォーカス復帰は既存のシートが受け持つ。

`LoadFailed` は基本部品の集約から外す。この部品の `$app/navigation` の依存まで集約すると、SvelteKit の payload を設定する前に env が評価され、版番号が空になる。`scripts/client-chunks.test.ts` は、この初期化順と別画面の遅延読み込みを小さい Vite ビルドで検査する。除外を外した設定では `/v1.2.3` が `/undefined` になり、このテストが失敗することを確認した。

依存パッケージ・ロックファイル・DB・APIの待ち時間・起動時の15秒判定・キャッシュ方針は変更しない。ビルド設定の変更のため `needs-human`。

## 比較条件

2026-11-14、変更前は `eece68f`、変更後は初回実装コミット `85d14a6` の差分。#1068 の計測手順を使い、同じベースで比較する。#1068 当時の `3812020` の JS 256.5kB/76件は履歴として残し、今回の前後比較とは分ける。

- Node 26.13.1、pnpm 12.12.0、Chromium 156.0.8078.4。
- `pnpm bench:boot --runs 2 --output <JSON>`。Fast/Slow 3G を各2回、ほかのビルドや検査と同時に走らせない。
- 公開seedの管理者、`/aoba`、1280×900、ja-JP、Asia/Tokyo、`simple_light`、gzip、新規コンテキスト、キャッシュとService Workerを無効化。
- 回線の数値・表示の判定・転送の集計は [開発手順](development.md#url-を直接開く最初の読み込みを測る) のとおり。kBは1,000Bで、CDPの転送量にはHTTPヘッダーを含む。
- 表示時までに完了した要求と、フォント完了・network idle後の総量を両方確認する。表示後へ転送を移しただけでは削減としない。

JSは4試行とも同じ集計。88件から47件（46.6%減）、297.0kBから238.1kB（19.8%減）。表示までに完了した全転送は560.9kB/104件から502.0kB/63件、安定後の総量は1022.2kB/118件から963.3kB/77件になった。Fastの失敗表示は前後とも0/2回。Slowは前後とも2/2回で、失敗表示の長さのp50は15,349msから2,850msへ短くなったが、失敗表示をなくしたわけではない。

Issueに記録されていた「50件以下」は達成。「230kB以下」は8.1kB超過しており、達成扱いにしない。完了条件の「転送量またはリクエスト数が減り、表示時間が悪化しない」は両方の回線の各試行で満たした。表示後へ要求を回しただけではなく、安定後のJS・総量も減った。

速度はローカルのworkerd/D1とCDPの回線制限によるもので、本番の配信遅延・端末のCPU・Brotliの保証ではない。

## 見た目と言葉

4テーマ（`simple`、`simple_light`、`simple_dark`、`modern`）で、変更前後の保存した本番ビルドを同じ使い捨てD1・公開seedで開いた。APIが返す本人のテーマとlocalStorageをそろえ、フォント完了とnetwork idleまで待って比較した。この表示比較では回線を制限せず、速度の計測結果には混ぜていない。

画面右下の版番号はビルドごとに変わるため、画像はその領域を除いて比較した。4テーマとも残る1280×880pxの画素が一致し、表示要素の位置・大きさ・色・書体・罫線も一致した。版番号が空になっていないことは別に確認した。開いていない起票シートのDOMと読み上げの状態領域は、遅延読み込みに伴って変わる。

`e2e/boot-javascript.test.ts` は4テーマでの初回本数、起票シートの遅延読み込み、本文編集、フォーカス復帰、取得失敗、連打と読み込み中の画面移動を確認する。セッションではE2Eを実行せず、CIの `e2e`・`e2e-dev`・`e2e-repeat` で確認する。

## 検査

初回実装コミット `85d14a6` の差分で `pnpm check`、`pnpm lint`、`pnpm format:check`、`pnpm test`、`pnpm build` が成功。Vitestは376ファイル・10,139件、Nodeのscriptsは2,007件成功・既存23件スキップ、CLIは248件成功。上の計測と4テーマの表示比較も、その後に実施した。

独立したコード・UI・反証QAを2巡行い、指摘を修正した。最後の「移動後・取得完了前のクリック」のキャンセル処理と、AppShellのSSRテストの期待値は2巡目の後に自己点検した変更。この段階ではセッションでE2Eを実行せず、その後のPRのCI・AIレビューで確認する。

PRのCI・AIレビュー対応では、操作対象idの保持、取得失敗からの画面再読み込み、通知の読み上げの重複解消を追加した。計測表はこれらの追記前の記録で、後続コミットの実測とはしない。E2Eは390pxの4テーマに加えて、計測と同じ1280×900px・`simple_light` でも50件以下と版番号を確認する。最新headのCI・レビュー結果はPRで確認する。
