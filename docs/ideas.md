# アイディア

要件として決める前のアイディアを書き留める。採用が決まったものは `requirements.md` に移す。

## 外部からの操作

- 遠隔の MCP（Worker の `/api/mcp`）で操作できる。手元の AI から使う stdio の MCP（`sg mcp`）は `requirements.md` に移した
- 画面上から Claude などの AI に指示して操作できる。案は `ai.md`

## AI

- ストーリーのタスク分割、ポイントの案、議事録からのストーリー作成、画面からの Claude の呼び出し。案は `ai.md`

## デイリークエスト

- タスクと関係のない毎日の習慣（メールの確認、問い合わせの確認、日報を書くなど）を設定できる

## ゲームらしさ

- 案内役のキャラクター（ギルドの受付係など）が、初めての操作やレベルアップの場面で声をかける。テーマごとの絵柄（シンプル、中世風、現代風で描き分けるか）と、スクラムの言葉のときに出すか、どう呼ぶか、出す回数と消し方（閉じる、二度と出さない設定）、原則 4（演出は短く1回で終わる）との関係が論点
- 効果音（クリア、レベルアップ、完了の印）。既定はオフで、本人が自分の設定でオンにする。素材（自作か使える条件の素材か）と、鳴らす場面をどこまで絞るか、設定をどこに持つか（ユーザーの設定か端末ごとか）、OS の設定（`prefers-reduced-motion` など）に合わせるかが論点
- レベル到達報酬。決まったレベルに達すると、見た目の飾りが付く（アバターの枠を銅、銀、金にする、称号、レベルアップの演出の種類など）。飾りは見た目だけにし、機能はレベルで解放しない。機能を解放にすると、入ったばかりの人ほど使えない道具ができ、組織の定額で払う機能がメンバーで違ってしまう。論点は次のとおり
  - 他の人に見える飾りは、`design.md` のレベルの紋章の決まり（形はどのレベルでも同じにして格の差を見せない、銅、銀、金は使わない）とぶつかる。決まりを改めるか、本人にだけ見える場所（自分のプロフィール、レベルアップの演出）に限るか
  - 打ち消しでレベルが下がったら、飾りも戻すか。到達した記録を別に持つなら、レベルを合計から毎回出す決まり（`requirements.md`）に例外を足すことになる
  - 呼び方。「報酬」は経験値を払う「クリア報酬」と紛れ、称号も言葉の辞書を通す語になる
  - 段階をどのレベルに置くか、テーマごとに描き分けるか

## ポモドーロタイマー

- 本人が作業の区切り（25分の作業と5分の休みなど）を計るタイマーを、全員が最初から使える。経験値はタスクの完了などの行動ごとに付くので（`requirements.md`）、タイマーは経験値に関係させず、計った時間も記録しない。論点は次のとおり
  - タスクにひも付けるか。ひも付けると、タスクごとの作業時間の記録（`requirements.md` で検討中の予実）に近づく
  - 画面を移っても止まらないように、どこに置くか
  - 終わりの知らせ。音は効果音のアイディア（既定はオフ、本人がオンにする）に合わせるか。ブラウザの通知は許可の取り方も決める

## ゲームの言葉

画面の言葉をゲームの言葉にできるようにする案。選べた頃の用語の対応を残す。言葉づかいを選ぶ口を戻すときは、組織の設定とワークスペースの作成のどちらで選ばせるか、選んだ言葉づかいをどの範囲（組織、ワークスペース）に効かせるかが論点。辞書（`src/shared/vocabulary.ts`）はスクラムの言葉の文字列だけを持つので、戻すときは、ゲームの言葉の文言を辞書に足すところから始める。

| 管理者 | ギルドマスター |
| ワークスペース | パーティ |
| リーダー | パーティリーダー |
| メンバー | 冒険者 |
| 受信箱 | 届いた便り |
| アーカイブ | 保管庫 |
| バックログ | 掲示板 |
| エピック | レイド |
| ストーリー | 達成目標 |
| タスク | クエスト |
| スプリント | 遠征 |
| スプリントゴール | 遠征の目的 |
| バーンダウンチャート | ボス戦 |
| 完成の定義 | パーティの掟 |
| エピックを作った人 | 依頼主 |
| エピックに参加するメンバー | 討伐隊 |

## アイディアを要件にする前の確かめ方

アイディアを `requirements.md` に移す前に、危ない前提を洗い出し、いちばん危ないものを、作る前に最小の手間で確かめる。確かめた結果は、そのアイディアの節に残す。

- 前提の種類: 利用者（本当に望むか）、問題（どのくらい起きて、どのくらい困るか）、解決（この案で足りるか。退けた別の案は何か）、効果（どの指標がどれだけ動くか。`requirements.md` の「成功指標」）、実現（作れるか。何を諦めるか）、定着（見つけて使い続けるか。行動の変化を求めるか）
- いちばん危ない前提は、外れたらアイディアごと成り立たなくなるもの。それに証拠があるかを先に見る
- 確かめ方は、作る前に済むものから選ぶ。自分のチームの聞き取り、画面の見本（`design/`）を見せる、手で運用して代える、の順に重くなる
- 案を1つに決める前に、別の案を5つ以上並べる。小さな手直しと大きな賭け、足す案と引く案、逆をやる案を混ぜる

### 今あるアイディアの危ない前提

どれも案で、確かめる前の見立て。

| アイディア | いちばん危ない前提 | 確かめ方（案） |
| --- | --- | --- |
| デイリークエスト | 仕事と関係のない習慣を、仕事の道具に置くと使われる。タスクの量が増えて、かえって本題が埋もれない | 自分のチームで2週間、手で運用する。完了を押す割合と、本来のタスクの完了数の変化を見る |
| 案内役のキャラクター | 初めての操作で声をかけると、迷いが減る。繰り返し出ても邪魔にならない | 初めての人に見本で通しで使ってもらう。閉じる回数と、迷って止まった場所を見る |
| 効果音 | 本人が自分でオンにするほど、鳴ることに価値がある | 既定オフのまま、オンにした人の割合を見る。ほとんどいなければ後回しにする |
| レベル到達報酬 | 見た目の飾りが、レベルを上げる張り合いになる。格の差として受け取られない | 見本（`design/`）に飾りの案を置き、自分のチームに見せる。張り合いになるか、比べられて嫌かを聞く |
| ポモドーロタイマー | 手元の別のタイマーではなく、Scrum Guild の画面で計りたい | 自分のチームで、作業の区切りを何で計っているかを聞く。決まった道具があれば後回しにする |
| 画面から AI に指示して操作する（`ai.md`） | 指示を書く手間が、画面で操作する手間より小さい | 手元の AI から `sg mcp` で同じ操作を頼み、実際にどの操作が頼まれるかを集める |

### 利用者の「仕事」の言い方

アイディアが誰のどの場面のためかを、「〜のとき、〜したい。そうすれば〜になる」で書いて、利用者像（`requirements.md` の「利用者像」）に当たるかを見る。当たらないアイディアは、先に利用者像のほうを疑う。

- 例: デイリークエストは、「毎日の習慣を忘れたくないとき、仕事の道具の中で済ませたい」。この仕事は、Scrum Guild が引き受ける仕事の範囲か（目的は、タスクを集めて薄く回すこと）。範囲外なら、採用しない判断も残す
