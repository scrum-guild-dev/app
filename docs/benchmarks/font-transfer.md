# 初回のフォント転送の比較（#1069）

## 採用した方法

`@fontsource/noto-sans-jp` の400・500・600・700・900の静的版から、同じ5.3.1（Google Fonts v57）の `@fontsource-variable/noto-sans-jp` へ切り替える。書体名はViteプラグインで `Noto Sans JP` にそろえ、既存のトークン・文字範囲・swap・各太さ・自前配信を保つ。太さの削除や擬似太字への置き換えはしない。

宣言は620個から124個、書き出すwoff2も620個から124個になる。CSSの転送目標100kB以下は達成した。Fontの目標300kB以下は未達だが、要求数と表示時間は改善した。

2026-11-09に人へ実測値を示して着地点を確認し、「可変版の改善を今回の成果とし、300kB目標は残件として記録する」と回答を得た。300kB以下は今回達成したことにせず、残件とする。

## 見た目と回帰の確認

元の静的版と可変版で、日本語・英数字を400・500・600・700・900で描き、4テーマの実際の色トークンを使った見本をChromiumで並べて比較した。代表文字列の20pxでの幅は全て一致（469、474、485、485、485px）。字形や太さの欠落は見られない。静的版と可変版では座標の丸めによるアンチエイリアスの差があり、400〜700の画像はピクセル単位では一致しない。900は一致した。

`e2e/fonts.test.ts` はアプリの4テーマで実際の見出し・本文・ポイントの書体と太さ（中世風の見出しは900、他は700、本文400、ポイント500）を確認し、その計算済みスタイルで日本語と数字のフォントを読み込む。テーマに依存しない5種類の太さの描画比較は1回だけ行い、日本語・英数字を1文字ずつ読み込んで各範囲の存在も確認する。日本語の代替書体をLatinの成功で見逃さない。CSP違反と外部フォント要求も検出する。このE2Eの実行はAGENTS.mdに従いCIに任せ、見本の描画比較とは区別する。
