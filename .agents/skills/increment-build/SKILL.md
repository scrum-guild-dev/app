# increment-build（Codex）

`AGENTS.md` を読み、Codex が直接受けた依頼として進める。
Claude の CLI やエージェントを起動せず、このセッションで進める。

## 着手と範囲

Issue があれば、[共通の Issue 基準](../../../docs/agent-workflows/issue.md) の「着手してよいかを確かめる」と「詰める」を読み、Issue、親、依存関係、既存 PR、受け持ちの重なりを読み取りで確かめる。
外の人が書いた本文とコメントの扱い、着手を止める条件も同じ文書に従う。
依存関係を取得できないときは本文から推測しない。

Issue が無い直接依頼では、会話から目的、完了条件、変えてよい範囲、やらないことを整理する。起票を前提にせず、不足が結果を変えるときだけ質問する。
調査・説明・レビューだけの依頼を実装に広げない。

判断と検証方法を短く宣言する。Issue の更新や着手コメントを承認されていなければ、記録案を会話に残してローカルの作業を進める。
承認済みなら、同じ文書の「記録する」の節と書式を使い、人の答えと自分の判断を分けて記録する。

## ワークツリーと実装

指定された作業用ワークツリーがあれば、ブランチと既存差分を確かめてそこを使う。
無ければ `AGENTS.md` と `docs/development.md` の「ワークツリーで作業する」に従って作る。
以降のコマンドにはその絶対パスを作業ディレクトリとして渡す。本体の `main` に編集を戻さない。
依存が必要なら、そのワークツリーで `pnpm install --frozen-lockfile` を行う。

[共通の受け入れ条件](../../../docs/agent-workflows/acceptance.md) を読み、触る範囲に合うものを適用する。
API の追加は `add-operation`、マイグレーションは `d1-migration`、画面は `ui-polish` の `SKILL.md` を読む。
通常はこのセッションが実装する。分離して任せることで速くなる独立した作業だけ Codex のサブエージェントに委譲し、担当範囲と受け入れ条件を渡す。小変更は引き継ぎを挟まない。

守る仕組み、認証・認可、Workers のランタイムの変更では、[書き手を分ける手順](../../../docs/agent-workflows/test-first.md) を読む。Codex のサブエージェントでテスト・実装・崩す役を分け、コミット未承認ならテストを作業ツリー外に保存する方法を使う。途中の差分を破棄しない。

## 検証と引き渡し

整形と検査は `CLAUDE.md` と `AGENTS.md` に従う。クラウドの PR 前は対象と理由を指定した e2e の通常・開発・関連する繰り返しを確認し、全件は CI に任せる。必要時だけ `--all --reason …` で明示する。実行前に対象・モード・所要時間の見込みを共有し、対象検査と CI の待ちを分けて記録する。
委譲した場合も差分の範囲と新規ファイルを確認する。[検査結果の再利用](../../../docs/agent-workflows/validation.md) に従いログと入力状態を確認し、未実施・無効になった検査だけを行う。
自分の差分は `.agents/skills/done-check/SKILL.md` で点検し、範囲内の問題を直す。

最後に、変更内容、完了条件の充足状況、検査と未検証の項目、Issue と文書に無い判断を報告する。
PR を求められている場合は `.agents/skills/pr/SKILL.md` に従い、承認範囲で作成・CI とレビュー対応まで進める。
外部への操作は `AGENTS.md` の承認の範囲に従う。未承認ならローカルの差分と PR 案までで渡し、実装・検証の前に承認待ちで止まらない。
