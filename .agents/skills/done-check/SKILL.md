# done-check（Codex）

[共通の点検基準](../../../docs/agent-workflows/review.md) を読む。Codex では以下の範囲・レビュー方法で進める。Claude の工程や CLI は呼ばない。

## 点検の範囲

作業ディレクトリとブランチ、既存の変更を確かめる。
ベースは指定があればそれを、PR があればその base を、無ければ通常 `origin/main` を使う。
`git diff <base>...HEAD` と `git diff HEAD`、`git ls-files --others --exclude-standard` の新規ファイルをすべて見る。
コミットがまだ無い実装を「差分なし」にしない。ベースの先端との差分に置き換えて、ベースだけの変更を逆向きに混ぜない。

Issue の完了条件と「やらないこと」を1つずつ突き合わせる。Issue が無ければ会話で決めた範囲を使う。
身に覚えのない変更は直したり戻したりしない。
範囲を広げる必要があれば、その理由を伝えて判断を求める。

## 機械的な検査と動作確認

共通の点検基準の「規約を読む」「機械で判定できるものを先に通す」「動かして確かめる」に従い、規約を読み、変更に合う検査を行う。
検査コマンドは `CLAUDE.md` を原本とし、整形は変更ファイルに絞る。[検査結果の再利用](../../../docs/agent-workflows/validation.md) に従い、工程が変わっただけでは再実行しない。
文書やスキルだけなら、リンク先、参照する節、メタデータ、設定の構文を検証する。アプリのテストを走らせたことにはしない。
マイグレーション、フック、画面の変更には、それぞれの追加検査を適用する。
ローカルで e2e を走らせない。クラウドでは PR 前に `pnpm e2e:preflight [base-ref]` を通し、対象コードと検査記録を確認する。PR が無い時点の CI は未検証として残す。

## レビューと修正

`.claude/skills/ai-review/reviewers.md` の手元（done-check）の列で必要な役割を選ぶ。
各役割の `.claude/agents/<役割>.md` と必要な `.claude/checklists/` を読み、観点と報告形式を共有する。
Claude のエージェントを名前で起動できるとは仮定しない。

Codex のサブエージェントが使える場合は、実装したのとは別のエージェントに必要な役割の点検を委譲する。小変更は選択表の「手元の小変更」に従い、別の1エージェントへ複数観点をまとめる。
渡すのは作業ディレクトリ、ベース、上の差分の範囲、該当するレビュー定義とチェックリスト、コードや外部サービスを書き換えずに報告する指示。
Claude の道具名やモデル指定は引き継がない。
独立したレビューが使えなければ、自分でも同じ観点で確認し、独立レビューは未実施と明記する。
自己点検だけで独立レビューを通過したとは報告せず、PR 案にも未実施を残す。

レビューは2巡までとし、追加の巡回は人が認めた場合だけ行う。Claude のレビュー予算フックを実行したり、効いていると仮定したりしない。
指摘は共通の点検基準の「直す」に従って、範囲内で直す。回帰をテストで防げるものは、先に落ちるテストを足す。
直さない CRITICAL と HIGH は、別のエージェントに `finding-verifier` の定義と指摘をそのまま渡す。
その検証ができなければ未判定のまま残し、自分の判断だけで指摘を取り消さない。
修正で影響する検査を再実行し、完了条件と範囲を最後の差分で確認し直す。

## 引き渡し

変更内容、完了条件ごとの結果、検査と動作確認、直した指摘、残った指摘と制約を報告する。
独立レビューに渡したときの HEAD と、未コミット・新規ファイルも含めた点検範囲を区別する。
レビュー後に直した差分は、そのレビューで確認済みとはしない。
未コミットの点検結果を、CI の差分省略に使う Claude 用の done-check 印に変換しない。
コミットや外部への書き込みは `AGENTS.md` の承認の範囲に従う。
